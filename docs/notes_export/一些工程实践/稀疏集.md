# 稀疏集

ECS架构中，需要由某一个entity快速定位其组件，并对其进行**增删改查**。如果使用简单数组，查找的时间复杂度为O(1)，但插入和删除的时间复杂度就大了，平均有O(n)。为了解决这个问题，**稀疏集**是一个很好的实践。

所谓**稀疏集**，其实就是指组件索引数组；而对应的是**稠密集**，指具体组件数组。

添加一个等长数组，专门用来存放到组件数组的索引，而这个数组本身的下标又是entity，这样，每次查找仍然是O(1)；删除已有组件时，我们采取和尾部组件交换的策略，并将稀疏集里原来的索引值置为-1，代表实体的该组件已被移除，时间复杂度仅为O(1)；插入类似，总是在稠密集现有组件集的末尾插，更新末尾新的元素值，将稀疏集对应元素设为插入位置，也仅需两步操作，时间复杂度O(1)。

由于一个实体只能有0或1个组件，所以任意一种组件的总数都是不大于实体最大数量的。

因此，我们可以根据自己游戏的情况，规定一个固定的最大实体数量。（若采用动态数组实现，也可以不固定）

entity通常用无符号64位整型，0表示不存在或非法。

头文件ecs.h:

```c
typedef uint32_t Entity; // 实体本质就是一个唯一ID
// #define ENTITY_NUM_MAX 1024 // 由用户定义

typedef struct {
	float x;
	float y;
} Position; // 位置组件

extern Position* positions; // 稠密集：具体组件数组
extern size_t pos_len; // 稠密集当前长度
extern int* pos; // 稀疏集：组件索引数组

bool ecs_has(int* sparse_set, Entity e);
void* ecs_comp(void* dense_set, int* sparse_set, size_t comp_size, Entity e); // 可以查、改
bool ecs_ins(void* dense_set, int* dense_len, int* sparse_set, const void* comp, size_t comp_size, Entity e);
bool ecs_del(void* dense_set, int* dense_len, int* sparse_set, size_t comp_size, Entity e, void* out);
```

从entity出发，查找它的组件：

`pos[entity]`​为-1则不存在(not has)，否则组件就是`positions[pos[entity]]`。

源文件ecs.c:

```c
#include "ecs.h"
...

Position positions[ENTITY_NUM_MAX];
size_t pos_len = 0;
int pos[ENTITY_NUM_MAX];

// 假定所有实体e输入，都在合法范围（1~ENTITY_NUM_MAX）内
bool ecs_has(int* sparse_set, Entity e) {
	return sparse_set[e] != -1;
}
void* ecs_comp(void* dense_set, int* sparse_set, size_t comp_size, Entity e) {
	if (!ecs_has(sparse_set, e)) return NULL;
	return dense_set[sparse_set[e] * comp_size];
}
bool ecs_ins(void* dense_set, int* dense_len, int* sparse_set, const void* comp, size_t comp_size, Entity e) {
	if (ecs_has(sparse_set, e)) return false; // 一个实体最多拥有一个同种的组件
	sparse_set[e] = *dense_len;
	memcpy(dense_set + dense_len * comp_size, comp, comp_size);
	dense_len++;
	return true;
}
bool ecs_del(void* dense_set, int* dense_len, int* sparse_set, size_t comp_size, Entity e, void* out) {
	if (!ecs_has(sparse_set, e)) return false;
	if (out) memcpy(out, dense_set + sparse_set[e] * comp_size, comp_size);
	dense_len--;
	memcpy(dense_set + sparse_set[e] * comp_size, dense_set + dense_len * comp_size, comp_size);
	sparse_set[e] = -1;
	return true;
}
```

> 实际项目中，还需考虑到**大组件**的存在，组件内部可以采用指针形式节省空间。在实现上，组件的删除也需要选择性地传递**清理函数回调**。

> 组件数组定义 在实际项目中，直接静态原生数组的方式容易导致**爆栈**。所以实际中推荐（且应该）采用**动态分配**的方式。这里为了简便就不改了。

main.c:

```c
#include "ecs.h"

int main(void) {
	memset(pos, ENTITY_NUM_MAX, -1); // 稀疏集初始化为-1.初始状态下实体是没有组件的（空实体）
	// 假定十个已经创建的空实体1~10。给它们添加position组件：
	for (int i = 1; i < 10; i++) {
		Position comp_pos = { 5.0 * i, 5.0 * i };
		ecs_ins(positions, pos_len, pos, comp_pos, sizeof(Position), i);
	}
	// 删除奇数ID实体的position组件：
	for (int i = 1; i < 10; i+=2) {
		ecs_del(positions, pos_len, pos, sizeof(Position), i, NULL);
	}
	// ... 其他的验证操作
	return 0;
}
```

**引擎本身最好不提供任何具体组件，只专注于提供API框架**（上例Position组件仅为了方便说明，实际不应该归引擎管）。内部这种`void*`方便扩展。使用该引擎API的应用可以自定义任何需要的组件，使用同一套ECS。

实际上，应用还应该对引擎暴露的这种“原始”API进行更符合人体工程学的封装。调用处，同一个ecs函数最多只涉及到三个变化，而其中有一个变化（何种组件）又是可以针对性封装解决的，所以游戏业务逻辑的编写者最多仅需决定应用层ecs操作函数和考虑两个变化的传递。
