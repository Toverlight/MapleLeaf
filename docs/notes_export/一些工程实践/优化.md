## 稀疏集相关

**ecs_** 前缀的函数，**增**和**删**都需要提供组件元信息。这些元信息可以被后来的[CompType](siyuan://blocks/20260713002148-144gg2d)取代：

`bool ecs_ins(void* dense_set, int* dense_len, int* sparse_set, const void* comp, size_t comp_size, Entity e)`​可以优化为**​`bool ecs_ins(CompType type, const void* data, Entity e)`​** 

类似地，`bool ecs_del(void* dense_set, int* dense_len, int* sparse_set, size_t comp_size, Entity e, void* out)`​可以优化为**​`bool ecs_del(CompType type, Entity e, void* out)`​** 

## 实体回收相关

还有**销毁实体**的[函数](siyuan://blocks/20260711220152-a3mngf3)，简化了参数、增加了反馈，因为默认全局就一个这样的组件注册表：

`void despawn_entity(Entity e, CompTypeReg* reg)`​可以优化为**​`bool entity_despawn(Entity e)`​** 

## 序列化与反序列化相关

### 接口定义的修改

```c
typedef char* Stream;
#define IMPL_INTERFACE_Serde(type, prefix) \
Stream prefix##_serialize_fn(struct type* obj); \
bool prefix##_deserialize_fn(struct type* obj, Stream stream);
```

### 外部实现

IMPL_INTERFACE移到外部，接着定义两个便捷宏，以与[WITH宏](siyuan://blocks/20260808102826-ztx1y9a)写法对接：

```c
// .h
DECLARE_COMP_BEGIN(Player)
	int hp;
	int def;
	float atk;
	int level;
	const char* name;
DECLARE_COMP_END(Player)
IMPL_INTERFACE_Serde(Player, player);
#define player_serialize() player_serialize_fn(_obj_self)
#define player_deserialize(stream) player_deserialize_fn(_obj_self, (stream))
```

源文件的实现不影响。（注意加后缀`_fn`）

实际上，这种方式是通用的。**凡是需要针对某个实例进行一连串的操作的，都可以用这种方式声明“成员函数”。** INTERFACE事实上是可选的，只是方便代码组织。

# 更好的结构与函数的组织方式

假定有一个`Point`结构体：

```c
typedef struct {
	float x;
	float y;
} Point;
```

它的**内部只放数据**。相关的**操作分离在外**（保持在同一份源文件中）：

```c
Point* point_move(Point* self, int dx, int dy) {
    if (self) {
        self->x += dx;
        self->y += dy;
    }
    return self;
}

Point* point_scale(Point* self, int factor) {
    if (self) {
        self->x *= factor;
        self->y *= factor;
    }
    return self;
}

Point* point_print(Point* self) {
    if (self) {
        printf("(%d, %d)\n", self->x, self->y);
    }
    return self;
}
```

实例化一个`Point`：

```c
Point pt = {10, 20};
```

如果按传统的链式调用方式，在C语言这边要：

```c
point_print(point_scale(point_move(&pt, 5, -3), 2));
```

这种层层往外包裹的编写方式“跨度”大（同时增加左右的代码），没有做到“链式”的单一方向性。删除某个“链”函数也是类似的麻烦。

## WITH宏

为了简化这个编写过程，我们可以用**WITH宏**封装（成员函数加了后缀`_fn`）：

```c
#define WITH(obj, ...) \
    do { \
        typeof(obj)* _obj_self = &(obj); \
        __VA_ARGS__; \
    } while (0)

// 宏语法糖，隐含_self
#define point_move(dx, dy)    point_move_fn(_obj_self, (dx), (dy))
#define point_scale(factor)   point_scale_fn(_obj_self, (factor))
#define point_print()         point_print_fn(_obj_self)
```

这样一来，涉及到链式调用时，我们可以更加方便：

```c
WITH(pt,
    point_move(5, -3);
    point_scale(2);
    point_print();
);
```

想要加新的调用、去掉某一个调用、更换调用顺序，都变得非常方便，只涉及到一行的更改。

> **==注意==**，**WITH宏的第一个参数**（对象体）**不能传临时对象**！（否则考虑下面的[WITH\_COPIED宏](siyuan://blocks/20260810140930-zpw6gh7)版本）里面没有拷贝操作。尤其是函数返回**值**的场景下，不能将函数直接放在WITH的`obj`参数位置！否则会造成指针悬空出现未定义行为！

事实上，WITH宏可以拆成`WITH_BEGIN()`​和`WITH_END()`。可能对高亮和提示更友好。两种方式都可取。为方便说明，这里还是采用第一种。

## WITH_COPIED宏

作为对WITH宏的补充。考虑到有些小结构体，复制开销小，同时也需要常规结构体的一些操作。

```c
#define WITH_COPIED(obj, ...) \
    do { \
        typeof(obj) _obj_self = (obj); \
        __VA_ARGS__; \
    } while (0)
```

使用：

```c
WITH_COPIED(entity,
	...
);
```

# 命名规范化

## 下划线开头的风险

根据 C 标准，**以两个下划线开头的标识符（**​ **​`__xxx`​**​ **）无论后面是大写还是小写，都是保留给实现使用的**，在任何作用域、任何情况下都不能由用户代码定义。违反这一点属于**未定义行为**。

- 以 `__`​ 开头的标识符：**始终保留，用于任何用途**。
- 以 `_` + 大写字母开头的标识符：同样始终保留。
- 以 `_` + 小写字母开头的标识符：仅在文件作用域（全局）保留。

**唯一能以下划线开头的命名情况是：单下划线 + 小写可以用在局部变量、静态变量、结构体成员上。** 除此之外都不可以！

## 分类情况（按优先级）

1. **文件内**​**==私有==**  
   ​`static`声明，小写snake_case：

   ```c
   static int internal_counter;
   static void parse_header(void);
   ```
2. **需要跨文件但“**​**==半私有==**​ **”（语义上内部，包括部分需要这种限制的枚举量）**   
   用项目前缀（或其特定简写） + 普通名字：

   ```c
   int myproj_internal_state;
   void myproj_helper_init(void);
   enum Abc { MYPROJ_Abc_Checklist, MYPROJ_Abc_OneTwoThree };
   ```
3. ==**结构体和枚举类型**==  
   大驼峰：

   ```c
   struct MyStruct {};

   enum Xyz { Xyz_One, Xyz_Two, Xyz_Three };
   // 或
   enum Xyz { One, Two, Three }; // 更简。如果比较常用
   ```
4. **仿**​**==成员函数==**  
   小写snake_case的结构体名称（或其特定简写） + 小写snake_case成员函数名称 + `_fn`后缀：

   ```c
   typedef struct {
   	float x;
   	float y;
   } Point;

   Point* point_move_fn(Point* self, int dx, int dy);
   ```
5. ==**常量和一般宏**==​ **（宏常量、宏包裹函数，不包括宏过程、宏函数）**

   全大写加下划线分隔：

   ```c
   #define MY_PI 3.1415926
   const double MY_PI = 3.1415926;
   ```
6. **==临时变量==**  
   小写snake_case 或 下划线开头后小写：

   ```c
   ({
   	int _tmp = ...;
   	xxx(_tmp, ...);
   });
   ```
7. 其他（**==默认情况==**）  
   小写snake_case。
