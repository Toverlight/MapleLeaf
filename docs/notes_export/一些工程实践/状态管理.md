# 状态管理

游戏的运行是经历不同状态的。游戏的状态可以按不同角度**划分**，状态可以是单一的或复合的。~~状态可能会有子状态，组织结构上是父子关系，但在状态转换上是同等的互斥关系。~~ 游戏任意时刻一定处于某种状态。

> 子状态的实现暂时不考虑。

> **划分：** 基于全集的，不重不漏的分类。

状态的一种划分的全体称为**状态集**。

状态的实现较为简单，就是基于枚举的一些封装和操作。

```c
// .h
#define DECLARE_STATE_SET_BEGIN() typedef enum {
#define DECLARE_STATE_SET_END(set_name) } set_name; \
void set_state_default_##set_name(set_name state); \
void reg_state_on_enter_##set_name(void(*on_enter)(set_name)); \
void reg_state_on_exit_##set_name(void(*on_exit)(set_name)); \
void change_state_##set_name(set_name state); \
void get_current_state_##set_name(void);

#define IMPL_STATE_SET(set_name) \
static set_name __current_state_##set_name; \
static void(*__on_enter_##set_name)(set_name) = NULL; \
static void(*__on_exit_##set_name)(set_name) = NULL; \
void set_state_default_##set_name(set_name state) { \
	__current_state_##set_name = state; \
} \
void reg_state_on_enter_##set_name(void(*on_enter)(set_name)) { \
	if (!__on_enter_##set_name) __on_enter_##set_name = on_enter; \
} \
void reg_state_on_exit_##set_name(void(*on_exit)(set_name)) { \
	if (!__on_exit_##set_name) __on_exit_##set_name = on_exit; \
} \
void change_state_##set_name(set_name state) { \
	if (__current_state_##set_name == state) return; \
	if (__on_exit_##set_name) __on_exit_##set_name(__current_state_##set_name); \
	if (__on_enter_##set_name) __on_enter_##set_name(state); \
	__current_state_##set_name = state; \
} \
void get_current_state_##set_name(void) { \
	return __current_state_##set_name; \
}
```

便捷宏：

```c
#define SET_STATE_SET_DEFAULT(set_name, state) set_state_default_##set_name(state)
#define REG_STATE_ON_ENTER(set_name, on_enter) reg_state_on_enter_##set_name(on_enter)
#define REG_STATE_ON_EXIT(set_name, on_exit) reg_state_on_exit_##set_name(on_exit)
#define CHANGE_STATE(set_name, state) change_state_##set_name(state)
#define GET_CURRENT_STATE(set_name) get_current_state_##set_name()
```

使用略。类似前面的。

> C语言枚举值是暴露全局的，因此它的命名建议用特定前缀的方式标明，表意明确且不易发生命名冲突（尤其是在包含大量头文件时）。
>
> **枚举值命名**建议格式：XXX_XxXxx（特殊大写前缀+大驼峰）

以上约束了应用对某种状态的依赖。但是状态对系统的运行条件影响等<u>暂时</u>不在引擎考虑范围内。原因是系统函数都是无参的、连续存储，利好CPU缓存，调用开销小。如果需要影响运行条件，只需在系统函数体开头取状态加个判断决定是否直接返回即可。
